### Question
Should order data be stored straight from the webhook payload, or should the webhook only trigger a refetch through the GraphQL Admin API?

### Options
1. Store the payload as is
2. Refetch via GraphQL using the ID from the payload

### Findings
- Reports that webhooks deliver addresses and similar fields as null or redacted even with protected customer data access approved. Shopify's intended pattern is "notify via webhook → fetch via Admin API" https://community.shopify.dev/t/orders-create-webhook-customer-data-is-redacted-even-after-protected-customer-data-approval/34610
- Product tags are not in the order data ("Need some fields not in order/id/.json" in the task)
- Shopify recommends reconciliation jobs rather than relying on webhooks alone https://shopify.dev/docs/apps/build/webhooks
