# 課題の解釈

[English](interpretation.md) | 日本語

> これは [interpretation.md](interpretation.md) の翻訳です。内容が異なる場合は英語版を優先してください。

課題の各解釈の理由を記載します。要約は [README](../README.ja.md#課題の解釈) にあります。

課題にはいくつか細部が定められていない点があります。このアプリは次の解釈に従います。

## CSV の行: 明細ごとに 1 行

各行は 1 つの明細です。注文の列(order id、number、total、customer、tags など)は、同じ注文のすべての行で繰り返します。注文の編集で削除された、または返金された数量 `0` の明細には行がないので、行は現在の注文と一致します。

これにより、1 行につき商品タイトルと商品タグが 1 組になり、スプレッドシートで絞り込みやピボットができます。

> **注:** 注文の列を繰り返すので、すべての行の *Total price* を合計すると、注文が明細の数だけ重複して数えられます。重複を除いた注文で合計してください。

## 商品タイトル: 商品自体のタイトルを優先

*Product title* は商品自体のタイトル(`Product.title`)で、下記の商品タグと同じ方法で取得・更新します。明細に商品がない場合(`productId` が null。[データベース設計](database.ja.md#データベース設計)の `LineItem` の行を参照)は、購入時に明細に記録されたタイトル(`LineItem.title`)を使います。

課題は *Product title* を "not in order/id/.json" のフィールドに挙げています。注文には各明細の購入時のタイトルが既に含まれているので、求められているフィールドは商品自体のタイトルと解釈しました。

## 商品タグ: その商品を含む注文と一緒に取得した値

商品タグは、注文を取り込むたび(`orders/create`、`orders/updated`、または同期)に注文と一緒に取得し、商品ごとに 1 回保存します。同期が取り込むのは未保存の注文と保存後に変更があった注文だけなので、変更のない注文の商品のタグは更新しません。その商品を含む注文を取り込むたびに、保存済みの商品のほうが新しくない限り書き込みます([データベース設計](database.ja.md#データベース設計)の `Product` の行を参照)。そのため、商品に紐づくどの明細にも同じ保存済みのタグが表示され、その明細の注文を取り込んだ時点のタグではありません。商品のない明細の *Product tags* セルは空です。タイトルと違い、購入時にタグは記録されないからです。アプリは商品の Webhook やイベントで商品を更新しないので、商品のタグの変更が反映されるのは、次にその商品を含む注文が取り込まれたときです。Shopify で削除された商品は、再び取り込まれない注文では保存済みのタイトルとタグのままです。

## 顧客の住所: 配送先を優先

*Customer address* は注文の配送先住所です。配送先がない注文(たとえばデジタル商品)は請求先住所を使います。
Shopify の住所の行(`formatted`、氏名なし)を `, ` で連結します。たとえば `123 Test Street, San Francisco CA 94103, United States`。

## 顧客の氏名とメールアドレス

*Customer full name* は注文の顧客の姓名です。*Customer email* は注文のメールアドレスです。どちらも空の場合があります。たとえば、顧客を選ばずに管理画面で作成した注文です。顧客を読むには `read_customers` スコープが必要です(#1)。

## 合計金額と数量: 現在の値をショップの通貨で

*Total price* は、ショップの通貨での注文の現在の合計(`currentTotalPriceSet`)です。返金、返品、注文の編集を反映し、税と割引を含みます。明細の数量は現在の数量(`currentQuantity`)なので、注文の編集で削除された明細は数量 `0` で残ると想定しています(API リファレンスから読み取ったもので、取得したレスポンスではまだ確認していません)。どちらも Shopify 管理画面の現在の注文と一致します。#1 で決定しました。

## CSV の形式

形式の表は [README](../README.ja.md#csv) にあります。

マーチャントは、注文一覧のタイトルバーにある **Export CSV** でファイルをダウンロードします。このボタンはショップに注文があるときに表示されます。ファイルにはショップの全注文が新しい順に入り、注文の行の順序は安定しています。ファイルはアプリのデータベースから作るので、エクスポートは Shopify API を呼び出しません。明細が残っていない注文にも 1 行あり、商品の列は空です。

[`samples/orders.csv`](../samples/orders.csv) はファイルのサンプルです。注文は架空のテストデータで、ストアからダウンロードしたものではなく、エクスポートと同じコード(`buildOrdersCsv`)で書き出しています。カンマ、引用符、数式セルなどのケースをまとめて示すためです。`test/domain/orders-csv-sample.test.ts` がこれらの注文を持ち、ファイルがエクスポートの出力と一致しなくなると失敗します。

## 配布方法: 公開

このアプリは公開配布を使うので、どのストアにもインストールできます。Shopify App Store には掲載していません。

## 注文一覧の列

注文番号、作成日時、顧客、メールアドレス、合計金額、決済ゲートウェイ、タグです。これらは、注文を一目で見分けるのに必要な CSV のフィールドです。全項目は CSV にあります。

注文はアプリのデータベースから新しい順に 1 ページ 25 件で一覧するので、ページの表示は Shopify API を呼び出しません。*Created at* はブラウザのタイムゾーンで表示します。アプリはショップのタイムゾーンを保存していないので、2 つのタイムゾーンが異なると Shopify 管理画面と違う表示になる場合があります。*Total* は注文に保存された通貨で、英語の形式(`$11.99`、`¥1,500`)で表示します。

## 注文タグ

マーチャントは一覧の注文の行からタグを追加します。タグは Shopify に送る前にチェックします。

| 入力 | 結果 | 理由 |
|---|---|---|
| 前後の空白 | 除去 | |
| 空 | 拒否 | |
| カンマを含む | 拒否 | `tagsAdd` は `a,b` を 2 つのタグに分割します |
| 55 文字超 | 拒否 | Shopify は 56 文字から `Order tags is invalid` と応答します。絵文字は 1 文字と数えます |
| 大文字小文字を問わず、注文に既にある | 拒否 | `tagsAdd` は `vip` を既存の `VIP` とみなし、何もしません |

上記の上限と動作は開発ストアで測定したものです(Admin API 2026-10)。ドキュメントには記載がありません。チェックには保存済みのタグのコピーを使うので、Shopify より遅れている場合があります。少し前に Shopify 管理画面で追加されたタグは検出できないことがあり、その場合 `tagsAdd` は何もしません。保存済みのコピーで見つかった重複は、注文の再取得(Admin API から読み直すこと)の結果と再度照合するので、少し前に Shopify 管理画面で削除されたタグは再び追加できます。

マーチャントはタグの隣のボタンでタグを削除します。`tagsRemove` は大文字小文字を区別して照合し、見つからないタグはエラーなしで無視するので、タグは保存されているとおりに送ります。上記のチェックは通らないので、他の場所で追加された、チェックで拒否されるタグも削除できます。レスポンスに大文字小文字を問わずそのタグがまだあれば、マーチャントにエラーを表示し、注文を再度保存します。これにより、再試行では Shopify にあるとおりのタグを使います。

タグの編集後、アプリは Webhook と同じ方法で注文を再取得し、全体を保存します([アプリが各注文を再取得する理由](adr/0003-refetch-order-via-graphql.md))。そのため、保存済みの `updatedAt` は常に注文のすべての列を表し、Shopify で何も変わらなかった編集(`orders/updated` が送られません)でもコピーは最新になります。編集より前の Webhook の取得は古いので、遅れて完了しても飛ばされます。再取得に失敗しても、編集は Shopify に届いているので、マーチャントには成功と伝えます。その編集の `orders/updated` がコピーを修復します。
